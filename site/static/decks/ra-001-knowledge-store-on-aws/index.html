RA-001 Knowledge Store on AWS

The reference architecture: Knowledge Store as one Terraform module on AWS

Reversed from the implementation at 0.3.0. Draft.

Context

One AWS account, one Terraform module, two applies. Ingestion as a Fargate sweep started by uploads; the record in S3; the graph in Neptune; the passage index on S3 Vectors; the tools behind AgentCore Gateway; the agent on AgentCore Runtime with Bedrock models and Guardrails; the page and API on CloudFront, API Gateway, Lambda and DynamoDB; sign-in with Cognito or a host website; images built in the account.

Non-goals

Multi-region, multi-account and a shared tenant model are out of scope: one deployment is one account and one stack.

Controls

Those of AP-001, plus: the origin secret between CloudFront and the API; reserved concurrency and the API throttle; the web ACL input; IAM authentication and private subnets for Neptune; a role per unit with a permissions boundary; the budget alert; images pinned by digest. The full table is security.md.

Cost

The cost table in aws/aws.md is the cost model: the Neptune instance is the fixed cost; everything else is per use; model calls are the cost that matters.
