# Design notes

The reasoning behind the architecture, written as it was worked out and kept as the record the catalogue under [docs/architecture](../architecture/README.md) points at. A note explains a design and the choices inside it; the catalogue registers the elements that came out of it, each with an identifier, and the decision records settle the choices. When a note and the catalogue disagree, the catalogue is corrected and the note says what changed.

| [Graph and document backends](aws/backends.md) | Optional Neo4j, Apache AGE and MongoDB projections behind the same API | ADR-008, SBB-011 |

| [Permissions, protection and classification from the source](source-controls.md) | How a document's permissions, protection and classification travel with its passages | CN-002, ADR-010 |
