# Architecture

The architecture of Knowledge Store, expressed with the [architecture continuum](https://github.com/dermot-obrien/architecture-continuum/blob/main/docs/continuum.md) and kept here, in the component's own repository, beside its implementation. It is reversed from the implementation at release 0.3.0: every page names the code that holds it today, and the findings where the code and the continuum's rules differ are recorded rather than hidden. How to install it on AWS is the [deployment guide](../deploy/aws/README.md).

## Checking it

`npm run check:architecture` runs the `aaa-continuum` skill over this folder: every page against its schema, every identifier against [the schemes register](registers/identifier-schemes.csv) and the folder it names, every register against its pages, every relation against the page it names and its inverse, the two pattern documents against their type, and every exported diagram against its render record. It is run by hand at checkpoints, not by CI, with warnings failing too. The skills are optional for everyone else, and [AGENTS.md](../../AGENTS.md) says how to install them.

## Reading it end to end

From the top: PL-001 owns three outcomes (OC-001 answers a reader can check, OC-002 an ontology the organisation owns, OC-003 a store run at a visible cost). Nine use cases realise them, each written before any design in the use-case skill's form, each fulfilled by features of PRD-001 and realised by the architecture pattern and its reference architecture. Thirteen capabilities say what must be possible; eight bounded contexts say where each model lives; fourteen architecture building blocks, each one C4 container, are the logical parts, each inside one context; fifteen solution building blocks name the technologies; AP-001 is the architecture pattern and RA-001 the reference architecture that applies it on AWS; nine services are the deployables, on sixteen nodes, with eighteen stores each owned by one context; ten decisions and six considerations say why, and what is still open.

From the bottom: pick a service in [runtime/services.csv](runtime/services.csv), follow `realises` to its SBB, `part_of` to its context, the context's `realises_capabilities` to the capabilities, and the capability's `required_by_outcomes` to the outcome. Every link is a field in front matter the skills validate.

## Conventions

- Front matter follows the continuum's [front matter standard](https://github.com/dermot-obrien/architecture-continuum/blob/main/standards/standard-frontmatter.md) and validates against its schemas; `.agents/skill-bindings.toml` binds each kind's folder for the skills.
- Prose: no em dashes inside sentences, no bold inside sentences, British spelling, one paragraph per line (the repository's CONTRIBUTING.md).
- Dates are the date the page was reversed, not the date the decision was made; `provenance.review_state` is `ai-raw` until a person reviews a page.
- Identifiers in body text are plain; the cross-reference skill turns them into links where a site renders them.

## Diagrams and decks

Each use case and pattern document is also a model and a deck. The `model` skill reads its Participants, Interactions, Interfaces and Scenarios tables, emits `components.drawio` beside it, validates the diagram against the document, stamps the exported `components.svg` (the `.render.json` is its record) and, for a use case, animates `scenarios.html`. The first layout of a diagram is by rank and is meant to be refined by hand in draw.io, then re-exported and stamped (`model.py stamp components.svg --diagram components.drawio --layer Structure`).

`npm run publish:decks` publishes every document marked `deck_publish: true` as slides and a PDF into `site/static/decks/<deck_id>/`, which is committed, and the site puts a "Slides · PDF" line under the title of each such page (`site/src/remark-deck-links.cjs`). The page is the source; the deck is regenerated from it at a checkpoint, never edited. Both scripts skip in one line when the skills are not installed (`npm run skills`, then `npm install` once in `.agents/skills/markdown-deck`); PDF export uses Edge or Chrome where installed, else `MARKDOWN_DECK_BROWSER` names a Chromium.
