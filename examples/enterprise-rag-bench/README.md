# EnterpriseRAG-Bench slice

A testbed for graph extraction on company knowledge: wiki pages, tickets, runbooks, threads and
mails of one invented company, Redwood Inference, with questions whose answers and source
documents are known. It is a slice of
[EnterpriseRAG-Bench](https://github.com/onyx-dot-app/EnterpriseRAG-Bench) (Onyx, MIT licence),
fetched by [`fetch.py`](fetch.py) and not committed here.

## Why this corpus

| What it tests | Where it comes from |
|---|---|
| Linking the same person, team, customer and project across documents of different kinds | The corpus was generated from one description of the company, so the same people and projects recur across Confluence, Jira, Slack, Gmail and the rest |
| Checking the graph, not only the answers | `reference/` holds that description: the employee directory (names, titles, managers), the project list and the initiatives. Extraction should find them |
| Keeping a superseded fact apart from the current one | Near-duplicate documents with specific facts changed; the `conflicting_info` questions ask for the current value and name both documents |
| Declining | 20 `info_not_found` questions that no document answers |

## Fetch

```bash
python examples/enterprise-rag-bench/fetch.py                     # writes examples/enterprise-rag-bench/data
python examples/enterprise-rag-bench/fetch.py out --distractors 3 # more neighbours per gold document
```

The full corpus is 5 GB and about 512,000 documents. The script takes the 722 documents the
questions cite and, for each, `--distractors` others from the same folder (1 by default: 1,438
documents and 12 MB in all, since some folders have no other document). The neighbours are chosen by a hash of their paths, so a run at
the pinned commit always fetches the same files. It needs PyYAML, which Knowledge Store installs.

| Written | Use |
|---|---|
| `documents/<source>/…json` | Upload to `landing/enterprise-rag/` (or the collection you name with `--collection`). Each file keeps its path in the benchmark |
| `reference/` | Do not upload. The company the corpus was generated from, to check extracted people, projects and initiatives against |
| `enterprise-rag-bench.yaml` | The evaluation set |
| `documents.jsonl` | The slice's document ids and paths, the `--answers-index` for grading another system's answers |

The documents are JSON records (a Jira issue, a Confluence page with its author, reviewers and
labels). The JSON parser reads each field as a labelled line, so the metadata reaches extraction
beside the text.

## The collection

```hcl
collections = {
  enterprise-rag = {
    profile = {
      name        = "Redwood Inference"
      description = "Internal documents of Redwood Inference, an AI inference company: wiki pages, tickets, runbooks, chat, mail and meeting notes. Generated by EnterpriseRAG-Bench; the company is invented."
      key_terms   = ["project", "initiative", "team", "customer", "incident", "runbook"]
    }
  }
}
```

## Evaluate

```bash
python -m knowledge_store.apps.evaluate examples/enterprise-rag-bench/data/enterprise-rag-bench.yaml --lake <lake> --model <model id> \
  --runner deepeval --grader deepeval --judge-model <judge model id> --yes
```

The grader judges each answer against the benchmark's gold answer (correctness), its answer facts
(completeness, the share stated) and the passages it cited (faithfulness). To compare Knowledge
Store with another system on the same questions and the same judge, write that system's answers
as the benchmark's harness takes them, one JSON object a line with `question_id`, `answer` and
`document_ids`, and grade the file; `--documents` lets faithfulness read what it cited:

```bash
python -m knowledge_store.apps.evaluate examples/enterprise-rag-bench/data/enterprise-rag-bench.yaml \
  --answers onyx.jsonl --answers-index examples/enterprise-rag-bench/data/documents.jsonl \
  --documents examples/enterprise-rag-bench/data/documents --grader deepeval --judge-model <judge model id> --yes
```

`fetch.py` writes `documents.jsonl`, the id-to-path index of the slice, beside the set.

To compare the graph with passage search alone, run the same agent with `--tools passages` after
`knowledge-store -c enterprise-rag embed` has written the lake's vectors (README, "Evaluate"):

```bash
python -m knowledge_store.apps.evaluate examples/enterprise-rag-bench/data/enterprise-rag-bench.yaml --lake <lake> \
  --model <model id> --tools passages --runner deepeval --grader deepeval --judge-model <judge model id> --yes
```

The set has the benchmark's questions except its 10 `high_level` ones, which have no gold
documents and summarise the whole corpus. Its types map to this repository's kinds:

| Benchmark type | Kind | Count |
|---|---|---|
| basic, semantic, constrained, miscellaneous, conflicting_info | lookup | 370 |
| intra_document_reasoning, project_related | multi-hop | 80 |
| completeness | list | 20 |
| info_not_found | unanswerable | 20 |

The benchmark states its answers as sentences (`answer_facts`), not as spellings a scorer can
match, so every answerable question is `judged: true`: the score checks that the agent answered,
cited one of the expected documents (`sources`), and that its claims pass the verifier. The gold
answer is in `expected` and the answer facts in `context`, for a grader that reads them. An
unanswerable question was judged absent from the whole corpus, so it is absent from the slice too.
